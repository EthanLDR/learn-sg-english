# Day 31 | Resolving conflicting requirements and confirming the source of truth

### Theme: 当 PM、设计、文档和后端说法不一致时，不猜，先指出冲突，再确认到底以哪个版本为准

今天练一个全栈工程师很高频的能力：**遇到两个不同要求时，把冲突、影响和最终依据说清楚。**

核心句：

- **I’m seeing two different requirements here.**
- **According to the design, the button should stay visible.**
- **That doesn’t match the current API behaviour.**
- **Which one should I treat as the source of truth?**
- **Just to make sure we’re aligned, we’re going with the design spec, right?**
- **Once that’s confirmed, I should be able to finish by Friday.**

同时复习：**I’m still waiting... / should be able to / by / on / before / future if**。

---

## 0–5 min | Warm-up

下面 5 句，每句大声说 3 遍：

> **I’m seeing two different requirements here.**  
> 我这里看到两个不同的要求。

> **According to the design, the button should stay visible.**  
> 按照设计稿，这个按钮应该一直显示。

> **That doesn’t match the current API behaviour.**  
> 这和现在 API 的行为不一致。

> **Which one should I treat as the source of truth?**  
> 我应该以哪个版本为最终依据？

> **Once that’s confirmed, I should be able to finish by Friday.**  
> 一旦确认下来，我应该能在周五前完成。

快速复习：

- **by Friday** = 最迟周五
- **on Friday** = 周五当天
- **before Friday** = 周五之前

Future if：

> **If we follow the design spec, I’ll update the frontend today.**

不是：

> **If we will follow the design spec...**

# 5–17 min | Office Communication & Meetings

## 5–9 min | 场景 1：设计稿和产品说明不一致

**Designer:**  
The submit button should stay visible even when the form is incomplete.

**You:**  
Got it. One thing I want to clarify: I’m seeing two different requirements here.

**PM:**  
What’s different?

**You:**  
According to the product notes, the button should be hidden until all required fields are complete. But according to the design, it stays visible and disabled.

**PM:**  
Let’s follow the design.

**You:**  
Okay. Just to make sure we’re aligned, it stays visible but disabled until the form is valid, right?

**PM:**  
Exactly.

实用结构：

> **According to A, ___. But B says ___. Which one should I follow?**

例如：

> According to the ticket, the field is optional. But the API documentation says it’s required. Which one should I treat as the source of truth?

重点不是指出“谁错了”，而是确认最终执行版本。

---

## 9–13 min | 场景 2：需求和 API 能力不一致

**PM:**  
Can we show the user’s live balance?

**You:**  
We can show a balance, but I want to flag one mismatch.

**PM:**  
What is it?

**You:**  
The requirement says “live balance”, but the current API only refreshes every five minutes.

**PM:**  
So what are our options?

**You:**  
Either we change the wording to “latest available balance”, or we ask backend for a real-time endpoint.

**PM:**  
Which is faster?

**You:**  
Changing the wording. I’m still waiting for backend to confirm whether a real-time endpoint is feasible.

**PM:**  
Let’s use the current API for this release.

**You:**  
Okay. If we keep the current API, I should be able to finish the frontend by Friday.

可复用：

> **The requirement says ___, but the current system only ___.**

> **We have two options: either ___ or ___.**

> **If we choose ___, I should be able to ___.**

---

## 13–15 min | 场景 3：会议结束前确认最终决定

**You:**  
Before we wrap up, I want to confirm the final decision.

**PM:**  
Sure.

**You:**  
For this release, we’ll keep the current API, show the latest available balance, and remove the word “live”. Correct?

**PM:**  
Correct.

**You:**  
Great. I’m still waiting for the final copy. If I get it by noon, I should be able to finish the page today.

记住：

> **Before we wrap up, I want to confirm...**

> **Just to make sure we’re aligned...**

> **Once that’s confirmed, I can move forward.**

## 15–17 min | 2-minute Oral Substitution Drill

连续开口，不要默读。

### Pattern 1

> **I’m seeing two different requirements here.**

替换：

- two different deadlines
- two different versions of the copy
- two different API expectations
- two different behaviours

### Pattern 2

> **According to the design, the button stays visible.**

替换：

- the ticket / the field is optional
- the API docs / the field is required
- the meeting notes / we release on Friday
- the latest message / testing must finish before Friday

### Pattern 3

> **If we confirm this by noon, I should be able to finish by Friday.**

替换：

- agree on the copy today / update the page tomorrow
- get backend confirmation by 2 p.m. / finish integration today
- finalize the design before Thursday / release on Friday
- choose Option A now / start testing this afternoon

# 17–23 min | Colleague Small Talk & Socializing

## 17–20 min | 场景 1：你听到的营业时间不一样

**Colleague:**  
That place downstairs closes at 8.

**You:**  
Really? I thought someone said it closes at 9.

**Colleague:**  
Maybe the hours changed.

**You:**  
Could be. I’ll check before we go.

自然表达：

> **I thought ___.**

> **I heard something different.**

> **Maybe it changed.**

> **I’ll check before we go.**

## 20–23 min | 场景 2：集合时间理解不一样

**Colleague:**  
See you downstairs at 6.

**You:**  
Six? I thought we said 6:30.

**Colleague:**  
I changed it in the group chat.

**You:**  
Got it. I must have missed that message. Six should be fine.

如果你还不确定：

> **I’m still waiting for a review. If it’s done by 5:45, I should be able to make it by 6.**

**I must have missed that message.** = 我应该是漏看了那条消息。

# 23–30 min | Restaurant / Shopping / Ride-hailing

## 23–25 min | Restaurant：菜单和店员说法不一致

**You:**  
Hi, the menu says this set comes with a drink, but I was told the drink isn’t included. Could I confirm which is correct?

**Staff:**  
The printed menu is outdated. The drink is no longer included.

**You:**  
Got it. Thanks for clarifying.

直接记：

> **The menu says ___, but I was told ___.**

> **Could I confirm which is correct?**

---

## 25–27 min | Shopping：网站和门店规则不同

**You:**  
I just want to clarify the return policy. The website says fourteen days, but I was told in store that it’s seven days.

**Staff:**  
Online orders have fourteen days. In-store purchases have seven.

**You:**  
Mine was an online order, so the fourteen-day policy applies, right?

**Staff:**  
Yes.

实用句：

> **Which policy applies in my case?**

> **So ___ applies to me, right?**

具体政策以商家真实规则为准。

# 30–35 min | Practical Singapore Life Errands

## 30–33 min | 场景 1：预约邮件和系统时间不同

**You:**  
Hi, I’m calling to confirm my appointment time. The email says 10 a.m., but the online portal shows 10:30.

**Staff:**  
The correct time is 10:30.

**You:**  
Great. Should I still arrive before 10:30 for registration?

**Staff:**  
Yes, please arrive about ten minutes early.

高频句：

> **The email says ___, but the portal shows ___.**

> **Could you confirm which time is correct?**

时间区别：

- **at 10:30** = 10:30 这个时间
- **before 10:30** = 10:30 之前
- **by 10:30** = 最迟 10:30 到

# 35–38 min | Common Grammar Fixes

今天只纠正确实有问题的表达。

### 1

**Wrong:** Which one I should follow?  
**Correct:** **Which one should I follow?**

直接疑问句里，助动词放在主语前面。

### 2

**Wrong:** According the design, the button should stay visible.  
**Correct:** **According to the design, the button should stay visible.**

固定搭配：**according to**。

### 3

**Wrong:** I have two different informations.  
**Correct:** **I have two different pieces of information.**  
**Correct:** **I’m getting conflicting information.**

**information** 是不可数名词。

### 4

**Wrong:** I’m still waiting your confirmation.  
**Correct:** **I’m still waiting for your confirmation.**

固定结构：**wait for + 人 / 事物**。

### 5

**Wrong:** If we will follow the design, I should can finish by Friday.  
**Correct:** **If we follow the design, I should be able to finish by Friday.**

Future if 条件从句通常用一般现在时；**should** 后不能直接接 **can**。

下面三句都正确，只是意思不同：

> **We need a decision by Friday.** = 最迟周五需要决定

> **We’ll review it on Friday.** = 周五当天 review

> **We need to resolve this before Friday.** = 周五之前解决

# 38–40 min | Final Speaking Challenge

## 第 1 分钟：Workplace Challenge

只看关键词说 45–60 秒：

**two requirements → design → API docs → mismatch → source of truth → waiting → by noon → should be able to → Friday**

参考：

> I’m seeing two different requirements here. According to the design, the field is optional, but the API documentation says it’s required. I don’t want to guess which version is correct, so could we confirm which one should be the source of truth? I’m still waiting for backend confirmation. If we get a decision by noon, I should be able to update the frontend today and still finish the full flow by Friday.

## 第 2 分钟：Everyday Challenge

关键词：

**appointment → email 10 → portal 10:30 → confirm → arrive before → correct time**

参考：

> Hi, I’m calling to confirm my appointment time. The email says 10 a.m., but the online portal shows 10:30. Could you confirm which time is correct? If the appointment is at 10:30, should I arrive before that for registration? I just want to make sure I’m following the latest information.
