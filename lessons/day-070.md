# Day 70 | What would count as done? Agree on clear acceptance criteria

### 今日主题：别人说“完成就行”时，先弄清怎样才算完成、用什么证据确认

今天的新技能是 **define the outcome → agree on a check → identify who confirms it → report the result**（明确结果 → 约定检查方式 → 确认由谁验收 → 汇报结果）。昨天练纠正误解；今天练在开始工作或办理事情前问清 **“什么情况才算真的完成？”**。这能避免做完 UI 却发现验收标准不同。

> **What would count as done for this task?** 这项任务怎样才算完成？
>
> **How will we know it's working as expected?** 我们怎么知道它符合预期？
>
> **Could we agree on two or three acceptance criteria?** 我们能先确定两三个验收条件吗？
>
> **Who needs to sign off before we close it?** 关闭任务前需要谁确认？
>
> **I'd like to verify the result before marking it as complete.** 我想先验证结果，再标记完成。

**acceptance criteria** = 可检查的验收条件；**sign off** = 正式确认或批准；**evidence** = 证据；**definition of done** = 团队约定的完成标准。注意：**implemented ≠ tested ≠ approved ≠ deployed**（实现、测试、批准、部署是不同状态）。今天只简短复习 **I'm still waiting for / should be able to / by、on、before / 未来 if 条件句**。以下均为模拟练习；真实业务和新加坡服务的状态以正式记录为准。

**严格 40 分钟：0–5（5）+ 5–17（12）+ 17–23（6）+ 23–30（7）+ 30–35（5）+ 35–37（2）+ 37–38（1）+ 38–40（2）= 40。** 所有准备、朗读、替换、独立输出和自检均在对应时段完成。

---

## 0–5 min | Warm-up：不只问“做完了吗”

**0–2 min｜四句各朗读三遍，剩余时间连成一段：**

> **What's the expected outcome?** 预期结果是什么？
>
> **What exactly should we check?** 具体应该检查什么？
>
> **Passing one test doesn't mean everything is ready.** 通过一项测试不代表所有东西都准备好了。
>
> **Let's confirm the criteria before we start.** 开始之前先确认标准。

**2–4 min｜两轮各一分钟；先读完整对话，再遮住 You：**

**PM:** Can you finish the new empty state today?

**You:** I can work on it, but what would count as done?

**PM:** The approved message should appear when there are no results.

**You:** Got it. Should we also check it on mobile and have QA verify the behaviour?

第二轮替换 **empty state → upload error state**、**no results → an upload fails**。用完整句区分“代码写完”和“行为已验证”。

**4–5 min｜先口译，再核对：**

“我还在等最终验收标准。” → **I'm still waiting for the final acceptance criteria.**

“如果中午前收到，我应该能最迟下午四点准备好测试版本。” → **If I get them by noon, I should be able to prepare a test build by 4 p.m.**

“我们怎样知道它真的完成了？” → **How will we know it's actually done?**

## 5–17 min | Office Communication & Meetings

### 5–9 min | Scene 1：AI 建议面板，什么才算开发完成

**PM:** Can we mark the AI suggestion panel as done?

**You:** The UI is implemented, but could we check the acceptance criteria first?

**PM:** What do you think we should verify?

**You:** The approved suggestions should render correctly. Users should be able to dismiss them, and loading and error states should be clear.

**Designer:** What about mobile?

**You:** We should include the agreed mobile layout and accessibility checks as well.

**PM:** When can QA start?

**You:** I'm still waiting for the final copy. If it arrives by noon, I should be able to share a test build by 4 p.m. QA would still need to verify it before we mark the task complete.

**5–7 min：**分角色朗读两轮；第二轮遮住 You。**7–8 min：**不看稿回答：What's implemented? Which checks remain? Who verifies? **8–9 min：**40 秒脱稿 + 20 秒自检：

> **The UI is implemented, but I'd like to verify ___. The acceptance criteria should cover ___, ___ and ___. I'm still waiting for ___. If ___, I should be able to ___ by ___.**

**render correctly** = 正确显示；**dismiss** = 关闭或忽略一条建议。不要把“可以交 QA”说成“QA 已通过”。

### 9–13 min | Scene 2：会议上将模糊需求变成可检验条件

**Lead:** We need the upload experience to be better.

**You:** Could we make “better” more specific before estimating the work?

**Lead:** What would you suggest?

**You:** Let's agree on the expected behaviour: a clear progress state, an actionable error message if an upload fails, and a success confirmation when it completes.

**QA:** How should we verify those?

**You:** We can list approved test cases for each state and record the actual results.

**Lead:** Who decides whether the requirement is met?

**You:** Let's confirm the product owner and QA responsibilities. We can then review the evidence before closing the ticket.

**9–11 min：**朗读两轮；第二轮替换 **upload experience → search experience**、**progress state → loading state**。**11–12 min：**按 **vague request → observable behaviour → test evidence → owner** 复述。**12–13 min：**60 秒自由说：

> **“Better” could mean different things. Could we define ___, ___ and ___? QA can check ___, and ___ can confirm whether the agreed requirement is met.**

**observable** = 能观察到的；**actionable error message** = 告诉用户下一步如何处理的错误提示。标准不需要听起来复杂，但应该能实际检查。

### 13–15 min | Scene 3：Code Review 已通过，不等于已经上线

**Reviewer:** I've approved the pull request. Can we close the release task?

**You:** Thanks for the review. The PR approval is complete, but the deployment and post-deployment checks are separate.

**Reviewer:** What still needs to happen?

**You:** The release owner needs to approve the rollout. After deployment, the agreed checks need to pass before we call the release complete.

**Reviewer:** Can you update the ticket?

**You:** Yes. I'll mark the code review as complete and leave the release status pending.

**13–14 min：**朗读并重读 **approved / deployed / verified**。**14–15 min：**40 秒脱稿说 **review done → rollout approval → post-deployment checks → status**，20 秒重复：**An approved PR isn't the same as a completed release.**

### 15–17 min | Timed oral substitution：12 轮 × 10 秒

**15:00–15:40｜A. 询问完成标准（4 轮）**

模板：**What would count as done for ___?**

1. the upload flow
2. the AI suggestion panel
3. the mobile layout
4. the accessibility fix

**15:40–16:20｜B. 说出可检查的结果（4 轮）**

模板：**We should verify that ___.**

1. the error message is clear
2. the loading state appears
3. the user can dismiss the suggestion
4. the approved layout works on mobile

**16:20–17:00｜C. 条件与期限（4 轮）**

模板：**If ___, I should be able to ___ ___.**

1. the copy arrives by noon / share the build / by 4
2. QA replies on Monday / update the ticket / on Tuesday
3. the test report arrives today / review the evidence / before Friday
4. the owner signs off by Thursday / send the summary / on Friday

每轮 **3 秒看提示 + 7 秒完整说句子**，总计 120 秒。**by Friday** = 最迟周五；**on Friday** = 周五当天；**before Friday** = 周五之前。

## 17–23 min | Colleague Small Talk & Socializing

### 17–20 min | Scene 4：同事约饭，怎样才算预订确认

**Colleague:** I've sent a booking request for our team dinner.

**You:** Nice! Is the table confirmed, or is it still a request?

**Colleague:** I'm still waiting for the restaurant to reply.

**You:** Got it. What confirmation should we look for before telling everyone it's booked?

**Colleague:** I'll check the booking channel for the final status.

**You:** Great. If it's confirmed by Friday, I'll share the details with the group.

**17–18 min：**朗读两轮。**18–19 min：**替换 **team dinner → weekend lunch**、**Friday → Thursday**。**19–20 min：**40 秒说 **request → confirmation needed → who checks → group update**；20 秒复读。

**booking request** = 预订请求；**confirmed booking** = 已确认的预订。不要把模拟场景当作真实订位。

### 20–23 min | Scene 5：团队活动报名，确认是否成功占到名额

**Colleague:** I signed up for the weekend badminton session.

**You:** Cool. Did you get a confirmation, or just a submission message?

**Colleague:** Only a submission message so far.

**You:** Ah, so the place might not be confirmed yet.

**Colleague:** Right. I'll check the final participant list.

**You:** Sounds good. I'm still waiting for my schedule. If I'm free, I should be able to give you an answer before Friday.

**20–21 min：**朗读。**21–22 min：**替换 **badminton → board-game event**、**participant list → organiser's confirmation**。**22–23 min：**40 秒按 **interested → submitted → confirmed? → follow-up** 复述，20 秒自检。

## 23–30 min | Restaurant / Shopping / Ride-hailing

### 23–25 min | Restaurant：扫码下单后如何确认真的下单成功

**You:** Excuse me, I tapped “Place Order”, but the screen didn't show a confirmation.

**Staff:** Please check the order status in the official ordering system.

**You:** What should I look for to know the order went through?

**Staff:** Check the order number and current status if they're available.

**You:** Thanks. I'll verify the order before trying again so I don't submit it twice.

**23–24 min：**朗读。**24–25 min：**替换 **Place Order → Pay Now**、**order number → payment status**。练 **action taken → expected confirmation → verify before repeating**。付款不明时不要直接重复支付。

### 25–27 min | Shopping：维修取件，先明确如何验证问题已解决

**You:** I'm here to collect my headphones after service. How can we confirm the reported issue has been resolved?

**Staff:** Please review the service record and any checks available under the store's process.

**You:** Thanks. Could we check the affected side and the connection before I acknowledge collection, if that's allowed?

**Staff:** Let's follow the official collection procedure.

**You:** Understood. I'll review the results and the paperwork.

**25–26 min：**朗读。**26–27 min：**替换 **headphones → keyboard**、**affected side → affected key**。区分“可以领取”和“问题已验证解决”；实际保修及测试流程以商家规定为准。

### 27–30 min | Ride-hailing：如何确认车是自己预订的

**Colleague:** Is that our car?

**You:** Let's check the vehicle details in the app before approaching it.

**Colleague:** What should match?

**You:** The registration number and other booking details shown in the app.

**Colleague:** And if something doesn't match?

**You:** We shouldn't assume it's our ride. Let's check through the app and use its support options if needed.

**27–28 min：**朗读两轮。**28–29 min：**替换 **car → taxi booking**、**registration number → displayed vehicle details**。**29–30 min：**40 秒脱稿说 **uncertain vehicle → matching details → confirmation → safe next step**，20 秒自检。不要仅凭车型或颜色判断。

## 30–35 min | Practical Singapore Errands

### 30–33 min | Scene 9：新加坡地址更新，什么证明修改已生效

**You:** Hi, I've submitted an address update request. How can I tell whether the change has actually taken effect?

**Support:** Please check the official status and any completion notice for the relevant service.

**You:** So a submission acknowledgement may not be the same as a completed update?

**Support:** Please refer to the agency's official status definitions.

**You:** Understood. Could you show me where I should verify the updated record?

**Support:** Please use the official service instructions for your type of record.

**You:** Thanks. I'll check the final record before treating the update as complete.

**30–31 min：**朗读。**31–32 min：**按 **request sent → status difference → official proof → completion** 复述。**32–33 min：**替换成 **bank contact-detail update**，问三句：**What counts as complete? / Where can I verify the updated record? / Is any further action required?** 不假定所有新加坡机构使用相同的地址更新流程。

### 33–35 min | Scene 10：手机套餐变更，确认什么时候生效

**You:** Hi, I've requested a change to my mobile plan. What should I check to know the new plan is active?

**Support:** Please refer to the provider's official activation status and plan details.

**You:** Does receiving the request confirmation mean the plan has started?

**Support:** Please check the stated effective date and activation guidance.

**You:** Thanks. I'm still waiting for the confirmation. If it arrives today, I should be able to review the plan details before Friday.

**33–34 min：**朗读。**34–35 min：**40 秒说 **request → effective date → active status → next check**，20 秒自检。费用、数据额度及生效时间以运营商正式说明为准。

## 35–37 min | Accurate Grammar Corrections

**35–36 min｜先独立修改前三句，再核对：**

1. ❌ **What does done looks like?** → ✅ **What does done look like?**（does 后接动词原形 look）
2. ❌ **Could you tell me how do we verify it?** → ✅ **Could you tell me how we verify it?**（间接问句使用陈述语序）
3. ❌ **We need to check if it works correct.** → ✅ **We need to check if it works correctly.**（修饰 works 使用副词 correctly）

**36–37 min｜复习两句：**

4. ❌ **I'm still waiting the acceptance criteria.** → ✅ **I'm still waiting for the acceptance criteria.**
5. ❌ **If QA will sign off today, I should able to update the ticket by Friday.** → ✅ **If QA signs off today, I should be able to update the ticket by Friday.**（普通未来 if 条件句用一般现在时；should be able to）

**正确替代，不算错误：** **What would count as done? / What does done look like? / How will we know it's complete?** 都自然；**Could we agree on the criteria? / Can we define the criteria?** 都正确；**check whether it works / check if it works** 都可用。**I'll update it by Friday / on Friday / before Friday** 都正确，但截止时间含义不同。

## 38–40 min | Final Speaking Challenges

### 38–39 min | Workplace：40 秒脱稿 + 15 秒对照 + 5 秒自检

提示：**AI suggestion panel → UI implemented → render, dismiss, loading/error, mobile → QA verification pending → final copy pending → if noon → test build by 4 → not release approval**。

**38:00–38:40：**不看参考，向 PM 确认完成标准。**38:40–38:55：**核对参考关键表达。**38:55–39:00：**检查是否区分实现、验收和发布。

> **The AI suggestion panel is implemented, but before we mark it as done, could we agree on the acceptance criteria? I'd check that the approved suggestions render correctly, users can dismiss them, and the loading, error and mobile states work as expected. QA still needs to verify the results. I'm still waiting for the final copy. If it arrives by noon, I should be able to share a test build by 4 p.m. That wouldn't mean the feature is approved for release yet.**

### 39–40 min | Everyday：40 秒脱稿 + 15 秒对照 + 5 秒自检

提示：**address update submitted → acknowledgement versus completed → ask official completion status → verify updated record → don't assume success**。

**39:00–39:40：**不看参考，向官方客服确认怎样才算完成。**39:40–39:55：**核对参考。**39:55–40:00：**自检有没有把提交当成修改成功。

> **Hi, I've submitted an address update request, but I'm not sure whether it's complete. Could you explain what confirmation I should look for? I understand that receiving a submission acknowledgement doesn't necessarily mean the new address has taken effect. Where can I verify the updated record through the official service? I'll check the final status before assuming the change is complete. Thank you.**

**40 分钟完成。今天最重要的一句：What would count as done, and how will we verify it?**
